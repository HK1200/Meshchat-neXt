Upstream: https://github.com/jade-on-mesh/meshcore-open-tak

## Initial implementation

Separate MeshCore announce-position layer, private-channel opt-in team mode, callsign/role/colour/status, explicit single position shares, tactical pins, alerts, trails, and SALUTE/general reports with withdrawal. Team datagrams use Open TAK datatype 0x5654 and published wire vectors for positions, pins, alerts. Four-byte aliases are not individually authenticated identities; no automatic contact linking. No automatic GPS, beaconing, TAK server, multicast or Reticulum bridge is started. Channel keys remain on the companion. Submitted channel items are not described as delivered.

## Region scoping review

Team group-data sends must follow the selected channel scope, using the existing serialized set/send/reset operation. Failure to reset closes the session. Test both named scopes and radio-default inheritance, and preserve the distinction between channel traffic and direct messages. Do not add region scoping to DMs.

Region names are not limited to three characters. Official guidance permits 29 UTF-8 bytes: https://blog.meshcore.io/2026/01/20/region-filtering . The firmware RegionMap has a 31-byte name buffer: https://github.com/meshcore-dev/MeshCore/blob/main/src/helpers/RegionMap.h . This is distinct from the 1–3 byte repeater path hash. Confirm app validation and display normalization against current firmware before widening supported characters. No Lynden/Whatcom examples or seeded region defaults in the shipped UI; regions come from user entry or discovery. Existing saved user settings must not be overwritten.

## Local geofence monitoring

Monitoring is a per-companion, per-selected-team opt-in preference, disabled by default. It observes received team positions only; no GPS polling or radio transmissions start when enabled. Circle and polygon/rectangle boundaries support entry, exit or both. Position uncertainty uses the larger of reported accuracy and a 10-metre margin. First observations, reconnects/restarts, configuration changes, boundary edits/deletion and receive gaps of 10 minutes establish fresh baselines. Consecutive identical observations do not refresh the baseline age or produce duplicate alerts.

Alerts use the existing MeshCore notification system and DND policy. They are separately controlled by the monitoring toggle, rather than ordinary channel chat mute settings. Taps resolve through the selected identity to the relevant map boundary. Pending events are invalidated when monitoring is disabled or boundaries change. Event history is bounded to 200 boundaries / 24 hours; crossing state is memory-only and bounded. No silent tracking of this phone is enabled.

Wire positions have no verifiable observation timestamp or individual sender authentication. Alerts describe received updates, which may be delayed or spoofed, rather than guaranteed real-time crossings. The UI makes that limitation explicit. This implementation detects a change between observed inside/outside states; it does not infer an unobserved pass-through between two outside positions.

### Tactical attachments: initial Codec2 voice-note implementation (2026-10-25)

Pins and SALUTE/general reports can now carry the Open TAK attachment reference (mode, four-byte session ID, packet count, duration/aspect field). The first supported attachment is a previewed Codec2 recording of up to 20 seconds. Recording/preparing/attaching is local; the separate Share pin/report action publishes the reference and explicitly makes that recording available to requesters. Downloads require a currently stored, active item in the selected owner/channel, and a full peer key matching its alias. No primary-radio fallback or automatic download is added. Published recordings remain available while cached (up to seven days, subject to cache eviction), including after removal of the map item; removal is not a remote-media revocation mechanism.

Following inspection of pinned upstream `team_map.dart`, normal sender selection uses known MeshCore contacts. ### Photos and voice in ordinary DMs/channels: local implementation and radio checks (2026-10-25)

Implemented shared photo preparation, preview, explicit send, requested downloads, cached image viewing and voice playback in ordinary MeshCore DMs and channels. Channel media uses Open TAK's `0x5643` channel-data request/response packets, scoped to the full channel identity. Every packet revalidates the live slot/key and selected scope; scope changes stop the transfer. Media control packets are consumed before chat storage, so they do not create unread messages or notifications. Existing announcement mute/mentions/banishment policy remains in place. Channel announcement state remains radio submission, not a DM delivery receipt. No primary-radio fallback or unsolicited media pushes were added.

Photos use version-1 VI1 AV1 OBUs and a 2,750-byte outgoing budget (up to 18 packets), with an exact decoded PNG preview. Receive supports version-1 and version-2 image payloads, at most 64 packets / 9,984 bytes and 1,024 pixels per side. Larger Open TAK Sharp/Super Sharp transfers are outside this initial receive limit; Mimi remains unsupported. Source JPEG/PNG/WebP files are limited to 10 MB, 40 megapixels and aspect 1:6 through 6:1. Bounded header inspection precedes browser decoding; only bounded RGB pixels reach the native encoder. Source EXIF/location/camera metadata and filename are not transmitted. The preview shows the transmitted quality and packet cost; no fixed airtime promise is made.

The checksum-pinned libaom build and MIT wrapper live under `native/av1` with a reproducible build script. Decoding checks the complete OBU sequence and reduced-still frame layout before full decode, preventing a later sequence header from bypassing the allocation limits. Applicable licenses/patent notices are bundled in backend data as `AV1_THIRD_PARTY_NOTICES.txt`. The arm64 Android build and host native round trips were tested; other ABIs/platform packaging still require their corresponding codec build. Builds without the optional library retain text/Codec2 functionality and report photo codec unavailability.

The same controls now support photo references on tactical pins and SALUTE/general reports. Attach prepares a reference locally; Share remains the separate publishing action. Tactical downloads keep explicit contact selection for ambiguous aliases, normal unique saved-contact lookup, and the raw-media unencrypted disclosure. Ordinary channel media uses the channel key; public channels are explicitly labelled non-private. OS notification formatting presents Photo/Voice labels rather than wire envelopes, without changing mute/mentions policy.
